# /harness-tune — 세션 종료 전 하네스 정비

**목표는 하네스를 정확한 상태로 유지하는 것이다.** 추가·수정·제거·압축은 전부 그 수단일 뿐,
어느 쪽도 그 자체로 목표가 아니다. 늘려야 할 때는 늘리고, 줄일 근거가 설 때만 줄인다.

네 가지 원칙:
1. **증거 없이 손대지 않는다** — 이번 세션에서 실제로 문제가 됐거나 사실이 틀어진 것만 다룬다.
2. **삭제는 세이프가드 통과 필수** — 보안 경계·골든셋 커버 규칙은 압축만 허용한다.
3. **사소한 것은 올리지 않는다** — 다음 세션의 행동을 바꾸지 못할 항목은 제안 목록에 넣지 않는다.
   **"개선 사항 없음"은 실패가 아니라 흔한 정상 결과다.**
4. **승인 없이 파일을 고치지 않는다** — 5단계까지는 읽기·분석만.

판정 기준 상세는 `references/criteria.md`에 있다. **2단계 시작 전에 반드시 Read 할 것.**

## 하네스 표면 (손댈 수 있는 범위)

| 층 | 경로 | 성격 |
|---|---|---|
| 규약 문서 | `CLAUDE.md`, `AGENTS.md`, `~/.claude/CLAUDE.md` | 매 턴 컨텍스트를 먹는 가장 비싼 층 |
| 강제 | `.claude/settings.json`(Stop·PreToolUse), `.claude/hooks/*.sh` | 기계적 차단 |
| 회귀 게이트 | `evals/harness/cases/**`, `evals/harness/lib` | 규약이 작동하는지 재는 골든셋 (라벨은 사람이 박제) |
| 절차 | `.claude/skills/*`, `.claude/commands/*` | 반복 작업의 결정 |
| 세션 간 기억 | `~/.claude/projects/-Users-hanms-freesign/memory/*.md` + `MEMORY.md` | 코드가 말해주지 않는 사실만 |

## 실행 절차

### 1. 인벤토리 + 증거 수집

```bash
wc -l CLAUDE.md AGENTS.md ~/.claude/CLAUDE.md .claude/settings.json .claude/hooks/*.sh \
      .claude/skills/*/SKILL.md .claude/commands/*.md 2>/dev/null
ls evals/harness/cases/*/ && ls ~/.claude/projects/-Users-hanms-freesign/memory/
git log --oneline -15 && git status --short
```

증거는 **세 갈래**로 모은다. 어느 갈래도 뒷받침하지 않는 제안은 추측이다.
- **현재 대화**: 사용자가 정정한 지점, 내가 헛다리 짚은 지점, 규칙이 없어 망설인 지점.
- **전사**(컨텍스트가 압축돼 초반이 사라졌을 때 필수):
  `bash .claude/skills/harness-tune/scripts/session_signals.sh <transcript.jsonl>`
  — **현재 세션 id를 인자로 넘기는 것이 기본이다.** id는 스크래치패드 경로에 들어 있고,
  전사는 `~/.claude/projects/<slug>/<id>.jsonl`이다.
  인자를 생략하면 `ls -t`(최근 **수정**순)로 고르는데, 세션을 여러 개 병행하면
  **다른 세션의 전사를 집는다.** 부득이 생략했다면 출력 첫 줄의 `# transcript: <경로>`가
  현재 세션 id와 같은지 반드시 대조하고, 다르면 id를 넘겨 다시 돌린다.
- **코드 현실**: 이번 세션의 diff와 커밋. 규칙이 참조하는 대상이 아직 존재하는지 `grep`으로 확인한다.

신호가 거의 없으면(문서 편집도, 마찰도, 정정도 없음) **"이번 세션은 튠 대상 없음"으로 보고하고 끝낸다.**
대부분의 세션이 여기서 끝나는 것이 정상이다. 보고할 거리를 만들려고 후보를 짜내지 않는다.

### 2. 후보 도출 — 4분류

`references/criteria.md`를 읽고 그 기준으로만 분류한다.

- **REMOVE** — 중복 / 죽은 규칙 / 훅·타입·테스트가 이미 강제 / 서술적 잡음
- **COMPRESS** — 규칙은 살리고 문장만 줄임 (복원 가능해야 함)
- **UPDATE** — 사실이 바뀌었거나 문서 간 드리프트 (특히 `CLAUDE.md` ↔ `AGENTS.md`)
- **ADD** — ADD 게이트 3문항(증거·재발성·층 적합성) 전부 통과한 것만

각 후보는 반드시 **경로:줄번호 + 인용 + 근거 한 줄**을 갖는다. 근거가 "일반적으로 좋다"면 버린다.

**유의성 기준** — 통과 못 하면 제안 목록에 올리지 않는다:
> 이 항목을 그대로 두면, 다음 세션에서 모델이나 사람이 **다르게 행동하게 되는가?**

오탈자·문체·용어 통일·줄바꿈·"조금 더 명확하게" 류는 전부 여기서 걸러진다.
네 분류의 건수를 맞출 필요는 없다. **ADD만 1건, 혹은 UPDATE만 1건인 결과도 정상이다.**
균형을 맞추려고 없는 삭제 후보를 만들지 않는다.

### 3. 세이프가드 검사 (REMOVE 후보 전량)

`criteria.md` §D를 항목별로 대조한다. 특히:
```bash
grep -rn "<지우려는 규칙의 핵심어>" evals/harness/cases/   # 골든셋이 이 규칙에 의존하는가
grep -rn "<규칙이 참조하는 심볼·경로>" src/ supabase/       # 대상이 아직 존재하는가
```
걸린 항목은 삭제 목록에서 빼고 **보류**로 옮긴다. 보류 사유도 리포트에 남긴다.

### 4. 제안 제시 (여기까지 파일 수정 없음)

번호를 매겨 한 화면에 보여준다.

```
### 제거 후보
1. CLAUDE.md:41 "..." — 중복: .claude/hooks/tdd-guard.sh가 이미 차단
### 압축 후보
2. AGENTS.md:18-24 (7줄 → 2줄) — 규칙 1개에 예시 5줄
### 수정 후보
3. AGENTS.md 기술스택 — CLAUDE.md와 드리프트(Polar·Resend·크론 누락)
### 추가 후보
4. CLAUDE.md 아키텍처 규칙 +1줄 "..." — 근거: 이번 세션 <구체적 사고>
### 보류
- CLAUDE.md:29 RLS 규칙 — 세이프가드 D-1(보안 경계)
```

그리고 **"적용할 번호를 알려달라(전체 / 없음 / 일부)"** 고 묻는다. 답을 받기 전에는 아무것도 쓰지 않는다.

### 5. 적용 + 검증

승인된 번호만 편집한다. 인접한 문장을 덤으로 손보지 않는다(외과적 변경).

- 규약 문서를 고쳤으면: `npx vitest run evals/harness` — 골든셋 균형·라벨 무결성 확인.
  `qa` 트랙은 라이브 `CLAUDE.md` 전문을 쓰므로, 지운 문장이 `must`/`must_not` 라벨의 근거였는지 다시 본다.
- `.claude/settings.json`을 고쳤으면: `python3 -m json.tool .claude/settings.json >/dev/null` 로 문법 확인 후,
  훅 명령을 셸에서 한 번 실제로 돌려 본다.
- 메모리를 고쳤으면: `MEMORY.md` 인덱스 한 줄과 파일을 반드시 동기화한다(추가·수정·삭제 모두).
- 전체 게이트(lint·build·test)는 턴 종료 시 Stop 훅이 자동으로 돌린다 — 여기서 중복 실행하지 않는다.

### 6. 리포트 (터미널 마크다운)

고칠 것이 없었으면 **한 줄로 끝낸다** — "하네스 튠: 이번 세션에서 나온 개선 대상 없음." 그리고 왜 없는지
한 줄만 덧붙인다(예: 마찰 신호 0건, 규약 위반·정정 없음). 표나 섹션을 비워서 출력하지 않는다.

있을 때만 아래 형식으로 쓴다. 없는 섹션은 통째로 생략한다.

```
## 하네스 튠 리포트 — YYYY-MM-DD

**적용: 제거 2 · 압축 1 · 수정 1 · 추가 1 · 보류 1** (문서 -37줄) | 검증: evals/harness ✅

### 제거 (2건)
- `CLAUDE.md:41` 테스트 선행 문구 — tdd-guard.sh가 동일 규칙을 기계적으로 강제

### 압축 (1건)
- `AGENTS.md:18-24` → 2줄 — 규칙 유지, 예시 5줄 제거

### 수정 (1건)
- `AGENTS.md` 기술스택 — CLAUDE.md 기준으로 Polar·Resend·TSA·크론 반영

### 추가 (1건)
- `CLAUDE.md` +1줄 — 근거: 이번 세션 <사고 요약>

### 보류 (1건)
- `CLAUDE.md:29` — 세이프가드 D-2(골든셋 review-04가 의존)
```

마지막에 커밋 여부를 묻는다(기본값: 커밋하지 않음). 승인 시 `chore(harness): ...` 로 main에 직접 커밋한다.

## 하지 말 것

- 승인 전 파일 수정, 승인 범위 밖 "김에" 정리.
- 증거 없는 예방적 규칙 추가, 예시·부연으로 문서 불리기.
- 반대로, 근거 없이 "줄여야 하니까" 지우기. 제거는 §C 기준을 입증했을 때만 한다.
- 유의성 기준을 통과 못 한 사소한 항목(오탈자·문체·용어 통일)을 목록에 채워 넣기.
- 보안 경계 규칙 삭제(압축만).
- 골든셋 케이스의 `expect`·`rule`·`must`·`must_not` 라벨을 모델 판단으로 바꾸기 — **라벨은 사람이 박제한다.**
  케이스 추가·수정이 필요하면 제안만 하고 사용자 확정을 받는다.
- 후보가 없는데 만들어 내기. "튠 대상 없음"은 정상적인 결과다.
