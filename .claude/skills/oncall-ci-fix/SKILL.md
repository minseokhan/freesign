# /oncall-ci-fix — CI 실패 사고 대응

사람이 시켜서가 아니라 **CI가 깨진 사실 자체가 트리거**다. 실패 잡 로그에서 근본 원인을 찾아
**최소 수정**을 워킹트리에 만들고, 무엇이·왜·어떻게를 `oncall-report.json`에 남긴다.

> 브랜치·커밋·PR은 만들지 않는다. 이 잡의 토큰은 `contents: read`라 푸시도 머지도 불가능하다.
> 워크플로의 다음 잡(결정적 스크립트)이 워킹트리 diff를 받아 PR을 연다.

## 경계 (어기면 사고다)

- **프로덕션은 읽기 전용.** 원격 DB·배포에 절대 쓰지 않는다. `supabase db push`·`supabase link`·
  `supabase migration up`·MCP `apply_migration`·`execute_sql`·`vercel deploy` 금지. 로컬 파일만 고친다.
- **`.github/` · `.claude/` · `.githooks/` 수정 금지.** 무한루프 게이트와 자동 머지 금지 경계가
  거기 있다. 이 경로가 diff에 섞이면 다음 잡이 PR을 열지 않고 실패한다.
- **시크릿을 리포트·코드에 옮기지 않는다.** 로그에 자격증명처럼 보이는 값이 있으면 값이 아니라
  "어떤 환경변수가 비어 있었다" 같은 사실만 적는다.
- **테스트를 지우거나 skip해서 통과시키지 않는다.** 기대값이 정말 틀렸다면 왜 틀렸는지를 리포트에
  적고 기대값을 고친다. 원인을 못 찾으면 못 찾았다고 쓰는 편이 낫다.
- 프로젝트 규약(`CLAUDE.md`)의 외과적 변경 원칙을 그대로 따른다. 인접 코드 리팩터링·포맷팅 금지.

## 절차

### 1. 실패 사실 읽기
`$ONCALL_LOG_PATH`(마스킹·꼬리 절단된 실패 잡 로그)를 Read 한다. 여기서 확인할 것:
- 어느 스텝이 죽었나 (`Audit` · `Lint` · `Build` · `Unit and integration tests` · E2E)
- **첫 번째 진짜 에러** (뒤따르는 연쇄 실패 말고). 스택트레이스의 최상단 프로젝트 파일 경로.
- 실패 개수와 패턴 — 한 파일인가, 전방위인가(전방위면 의존성·설정·환경 쪽 의심).

### 2. 가설 세우고 코드에서 확인
로그의 파일·심볼을 Grep/Read로 확인한다. `git log --oneline -10`·`git show --stat HEAD`로 이번
커밋이 무엇을 건드렸는지 본다. 로그가 가리키는 곳과 최근 변경이 겹치는 지점이 대개 원인이다.

원인 유형별로 흔한 것:
- 타입 에러/빌드 실패 → 시그니처 변경 후 호출부 누락, `types/database.ts` 재생성 누락
- 단위 테스트 실패 → 순수 함수 동작 변경 vs 기대값 노후화 (**어느 쪽이 옳은지 반드시 판단할 것**)
- lint 실패 → 규칙 위반 (규칙을 끄지 말고 코드를 고친다)
- `npm audit` 실패 → 프로덕션 의존성 취약점. `package.json`/`package-lock.json` 버전 상향
- E2E 실패 → 셀렉터 노후화 vs 실제 회귀. 판단이 안 서면 고치지 말고 리포트에만 적는다

### 3. 최소 수정
재현 → 수정 → 재확인 순서로 좁게 간다.
- 해당 테스트만 먼저: `npx vitest run <파일>`, `npm run lint`
- 그 다음 전체: `npm run lint && npm run build && npm test`
- 실패의 근본 원인 한 곳만 고친다. 눈에 띈 다른 문제는 **리포트에 적고 고치지 않는다.**

### 4. 리포트 남기기 (필수)
저장소 루트에 `oncall-report.json`을 Write 한다. **이 파일이 없으면 PR은 열리지 않는다.**

```json
{
  "title": "무엇이 깨졌나 — 한 줄 (예: vitest 3건 실패 · src/lib/tax.ts)",
  "rootCause": "왜 깨졌나. 어느 커밋/변경이 어떤 경로로 실패를 만들었는지 근거와 함께.",
  "fix": "어떻게 고쳤나. 파일별로 무엇을 왜 바꿨는지. 다른 선택지를 버린 이유도.",
  "unresolved": "남은 위험·사람이 판단해야 할 것. 없으면 '없음'."
}
```

- 한국어로 쓴다. 마크다운을 써도 된다(PR 본문에 그대로 들어간다).
- **확신이 없으면 확신 없다고 쓴다.** 이 PR은 사람이 읽고 머지 여부를 정하는 물건이다.
- 원인을 못 찾았으면 코드를 바꾸지 말고 `rootCause`에 조사한 내용과 막힌 지점을 적는다
  (변경이 없으면 PR 대신 잡 요약으로 보고된다).
