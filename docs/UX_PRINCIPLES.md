# UX 원칙 — 매듭

> Figma의 [7 UI Design Principles](https://www.figma.com/resource-library/ui-design-principles/)를 매듭의 실제 플로우("계약 → 서명 → 청구 → 입금 → 세금 정리")에 적용한 문서. **핵심 목표: 인지 부하를 줄이고, 명확한 시각 피드백으로 논리적 워크플로를 안내한다.** 구체적 색·타이포·컴포넌트 스펙은 `UI_GUIDE.md` 참조.

프리랜서는 한 달에 3~4명을 상대하며 정산 도구를 **빠르게 열고 빠르게 닫는다.** 화려함이 아니라 "내 돈이 어디까지 왔나"를 3초 안에 읽히게 하는 것이 이 제품의 UX 성공 기준이다.

---

## 1. 계층 (Hierarchy) — 가장 중요한 정보가 가장 먼저 읽힌다
크기·굵기·색·여백으로 주목도를 설계한다.

- **대시보드**: `미수금 합계`·`이달 수익`·`이번 달 예정 입금` 3개를 최상단 KPI로 가장 큰 타이포(`text-3xl` tabular-nums). 그 아래 `계약 파이프라인`(초안→서명완료→진행중→완료 단계별 건수) 섹션, 이어서 임박/지연 리스트, 채널 수익 TOP 위젯 순.
- **계약/인보이스 상세**: 제목 → 상태 배지 → 금액 → 본문(조항·원천징수 내역) → 이력 타임라인 순으로 시선이 내려가게.
- **1화면 1주요 액션**: 각 화면의 primary 버튼(발행·서명·확정)은 남색 1색으로 단 하나만 강조. 나머지는 secondary/text.
- 금액과 상태는 항상 본문보다 무겁게(굵기·색) — 프리랜서가 스캔으로 읽는 두 값이므로.

## 2. 점진적 노출 (Progressive Disclosure) — 한 번에 다 보여주지 않는다
복잡한 플로우를 단계로 쪼개고, 진행 위치를 알려준다.

- **`/contracts/new` AI 초안 플로우**: `구조화 입력 → 초안 생성 → 저장`(3단계)을 스텝으로 분리하고 **현재 단계 표시**(스텝 인디케이터). 조항 편집은 저장 후 별도 페이지(`/contracts/[id]/edit`)로 분리해 폼 전체를 한 화면에 쏟지 않는다.
- **원천징수**: 인보이스 작성 시 `withholding_type` 선택 후에야 계산 내역(소득세·지방세·실지급)을 펼쳐 보여준다.
- **설정 온보딩 강제 없음**: 계좌·기본 원천징수율은 첫 인보이스에서 빈 값일 때 인라인으로 안내(미리 다 요구하지 않음).
- **이력 타임라인**: 상세 하단에 항상 펼쳐진 타임라인으로 증빙 체인을 확인(접기/펼치기 상호작용 없음).

## 3. 일관성 (Consistency) — 같은 것은 같게 동작한다
반복 패턴으로 학습 비용을 없앤다.

- **상태 배지**: 계약(draft/signed/active/done/canceled)·인보이스(draft/unpaid/paid/overdue)를 **동일한 pill 형태 + 시맨틱 색 규칙**으로. 완료=green, 대기/임박=amber, 미수/지연=red, 중립=slate. 화면이 달라도 색 의미는 불변.
- **CRUD 레이아웃 통일**: 클라이언트·계약·인보이스의 목록/상세/폼이 같은 구조(목록=테이블+필터, 상세=헤더+본문+타임라인, 폼=좌측 라벨).
- **액션 버튼 위치 고정**: primary는 항상 우상단(또는 폼 하단 우측), 삭제(soft-delete)는 항상 danger 스타일.
- **날짜·금액 포맷 통일**: 금액 `₩` 접두 + tabular-nums, 날짜 `YYYY.MM.DD`, 원천징수·수익은 KST 기준(§ARCHITECTURE).

## 4. 대비 (Contrast) — 중요/위험을 색으로 즉시 구분
- **파괴적 액션은 red**: 계약 취소·soft-delete·`paid→unpaid` 되돌리기 등은 red 계열로 명확히 경고. 일반 액션은 블루, 보조는 중립.
- **정산 신호**: 미수·지연은 red, 임박은 amber, 입금 완료는 green으로 대시보드에서 튀게. 신호색은 **상태 표현에만** 쓰고 일반 강조엔 안 써서 희석 방지.
- **면책 배너**: AI 초안·원천징수 "참고용" 고지는 amber 배너로 눈에 띄되 액션을 막지 않게(비차단 경고).
- 배경-텍스트 대비는 WCAG AA 이상(§접근성).

## 5. 접근성 (Accessibility) — 누구나 쓸 수 있게
WCAG 기준을 지킨다.

- **색 대비**: 본문 텍스트 4.5:1, 큰 텍스트/UI 3:1 이상. 상태를 **색만으로 구분하지 않고** 텍스트 라벨(입금완료/미수/지연) 병기 — 색각 이상 사용자 대비.
- **키보드 내비게이션**: 모든 인터랙션(폼·토글·서명 완료·탭)은 키보드로 도달·조작 가능. 포커스 링 명시(블루 ring).
- **캔버스 서명 대안**: 터치/마우스 서명 불가 상황 대비 안내, 라벨·aria 속성 부여.
- **폼 접근성**: 라벨-인풋 연결, 에러는 `aria-describedby`로 필드에 연결, 충분한 터치 타깃(최소 44px)·패딩.
- **이미지/아이콘**: 의미 있는 아이콘엔 alt/aria-label, 장식용은 `aria-hidden`.

## 6. 근접성 (Proximity) — 관련된 것끼리 묶는다
- **계약 상세**: 조항+평문요약을 한 카드, 서명+PDF를 한 그룹, 하위 인보이스를 별도 섹션, 이력을 하단 타임라인으로 **기능 단위 그룹핑**.
- **인보이스 폼**: 금액·원천징수·실지급을 한 블록(계산 관계가 있으므로 붙임). 지급기한·발행은 다른 블록.
- **위험 액션 분리**: 삭제·취소·되돌리기는 일반 액션과 물리적으로 떨어뜨려 오클릭 방지.
- **대시보드 위젯**: KPI / 임박·지연 / 채널 TOP을 카드 경계로 명확히 구분.

## 7. 정렬 (Alignment) — 그리드로 예측 가능하게
- **그리드**: 대시보드·리포트는 일관된 그리드(카드 정렬), 상세 폼은 좌측 라벨 정렬로 스캔 라인 형성.
- **숫자 우측 정렬**: 목록의 금액·미수액은 우측 정렬 + tabular-nums로 자릿수 비교가 쉽게.
- **여백 리듬**: 섹션 간 일정한 간격 토큰(§UI_GUIDE 스페이싱)으로 시각적 질서.
- 좌측 정렬 기본, 중앙 정렬은 빈 상태(empty state) CTA 등 예외에만.

| 단계 | 적용 원칙 | UX 판정 기준 |
|------|-----------|--------------|
| ① 첫 진입(빈 화면) | 점진적 노출·계층 | 빈 화면 공포 없이 "데모 채우기" CTA가 즉시 보인다 |
| ② 클라이언트 등록 | 근접성·일관성 | 채널 태그 선택이 직관적, 목록에서 채널 배지로 스캔 |
| ③ AI 계약 초안 | 점진적 노출·대비 | 스텝별 진행 표시, `[검토 필요]` 플래그가 대비로 눈에 띔, 면책 노출 |
| ④ 서명·PDF | 계층·접근성 | 서명이 1주요 액션, 완료 후 상태 배지·PDF 버튼 명확 |
| ④' 계약 불러오기(성사) | 점진적 노출·일관성 | 기존 계약 PDF 업로드 → 서명 없이 성사(signed)로 저장(`createImportedContract`), 이후 인보이스 흐름 동일 |
| ⑤ 인보이스 발행 | 근접성·점진적 노출 | 원천징수 계산이 선택 후 펼쳐짐, 계좌 미입력 시 인라인 경고 |
| ⑥ 정산 토글 | 대비·일관성 | 입금 완료=green, 미수=red 즉시 구분, 낙관적 UI 즉시 반영 |
| ⑦ 대시보드 | 계층·정렬 | 3초 안에 미수금·이달 수익·임박/지연이 읽힘 |
| ⑧ 세금 CSV | 일관성·점진적 노출 | 연도 필터 → 내보내기 한 번, 기준(paid_at/issue_date) 명시 |

## 상태·피드백 원칙 (크로스커팅)
- **모든 상태 존재**: 로딩(`loading.tsx` 스켈레톤)·빈 상태(문구+CTA)·에러(`error.tsx`)·성공(토스트)을 각 화면마다 정의. "데이터 있음"만 디자인하지 않는다.
- **즉각 피드백**: 정산 토글은 `useOptimistic`로 즉시 반영 후 실패 시 롤백+토스트. 제출 중 버튼 비활성(이중 제출 방지).
- **비파괴 안심**: soft-delete·데모 채우기/지우기는 되돌릴 수 있음을 문구로 안내. paid 인보이스 하드삭제 차단. **계약은 물리 삭제(ADR-008 갱신)** 라 확인 문구가 "완전히 삭제됩니다 · 되돌릴 수 없습니다"로 실체와 일치하고, 딸린 인보이스는 유지됨을 함께 안내한다(스냅샷 보존). *(인보이스 자체 삭제 UI는 여전히 이 원칙 미반영 — 실제 soft-delete인데 문구가 "되돌릴 수 없습니다"이고 paid 가드 없음, 보완 필요.)*

## 브랜드 용어 "매듭" 카피 원칙

브랜드명이 한글 단어이므로 UI 카피에 녹여 쓰되, **계약을 완결짓는 행위에만** 쓴다.
목록·조회·수정·삭제 같은 중립 동작에는 쓰지 않는다(남용하면 의미가 닳는다).

| 위치 | 카피 |
| --- | --- |
| 계약 생성 CTA | 계약 매듭짓기 |
| 빈 상태 | 아직 매듭지은 계약이 없습니다 |
| 서명 완료 | 서명이 완료되어 계약이 매듭지어졌습니다 |

> **DB enum·status 값·이벤트 타입은 절대 바꾸지 않는다.** 화면에 보이는 라벨만 바꾼다.
